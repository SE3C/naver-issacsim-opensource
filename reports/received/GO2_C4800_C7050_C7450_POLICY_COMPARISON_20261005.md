# Go2 C4800 · C7050 · C7450 정책 심층 비교

- 작성일: 2026-10-05
- 입력: 정책별 Windows 통합 ZIP 3개
- 범위: ZIP 내부 평가 원자료(`episodes.jsonl`, `diagnostics.json`, manifest/config/log)와 루트 MP4 18개 직접 조사
- 성격: **PERSONAL camera-off 진단 + 고정 6지형 정성 영상**. 공식 점수나 공식 제출 결과가 아니다.

## 1. 결론

### 최종 판단

| 정책 표시명 | 후보 판단 | 핵심 판단 |
|---|---|---|
| **C7450** (`model_7450.pt`) | **PROMOTE** | 세 후보 중 가장 균형이 좋다. C7050보다 9개 case 중 8개에서 평균 tracking error가 낮고, 8개에서 body-frame 전진 적분이 크다. 계단 성능 개선이 특히 크며 stall도 가장 낮다. 단, C7050보다 stair-up base-contact 종료가 2→4회로 늘고 `action_delta_rms`·`roll_pitch_rms`가 커지는 안정성/부드러움 비용이 있다. |
| **C7050** (`model_7050.pt`) | **HOLD** | 매우 안정적인 대안이다. 3,456 cohort 중 stair-up 2개만 terminated되고 stair-down은 0이며, 전체 action 변화량도 세 후보 중 가장 낮다. 다만 C7450보다 대부분 case에서 추종·진행이 뒤지고 계단 하행 stall이 눈에 띄게 높다. **안전성 우선 fallback**으로 보존할 가치가 있다. |
| **C4800** (`g2-submit-3_model_4800.pt`) | **REJECT** *(현재 all-around 후보 기준)* | 평지 전진, rough/randomized, push의 평균 tracking은 일부 더 좋고 비계단 자세/행동 비용도 낮은 편이다. 그러나 계단에서 15회 base-contact 종료, 높은 stall, 낮은 진행, 매우 큰 tracking tail이 집중되어 일반 Go2 후보로는 두 정책보다 명확히 불리하다. |

**현재 정책 후보는 C7450을 채택하는 것이 타당하다.** C7050 대비 생존 열화는 실제로 존재하므로 무시하지 않지만, 4회의 종료가 모두 `stairs_up/seed=4201`에 집중되고, 같은 seed를 포함해 stair-up 평균 tracking과 진행은 C7450이 더 좋다. 즉 C7450은 “더 잘 가지만 제어가 더 거칠고 특정 계단 상행 초기조건에서 드물게 더 넘어지는” 정책이다. 현재 자료의 목표가 생존만이 아니라 **진행·추종·지형 통과·회복**을 포함한다는 점에서 C7450의 이득이 더 크다.

C4800은 반대로 평지/rough 계열의 좋은 추종 신호가 있어 정책 자체가 무용한 것은 아니지만, stairs가 목표 범위에 포함된 이상 현재 경쟁 후보 둘을 두고 선택할 이유가 약하다.

## 2. 정책 identity와 비교 조건

### 입력과 checkpoint 연결

| 표시명 | ZIP의 source checkpoint | checkpoint SHA-256 | 평가 상태 | protocol | seeds / envs | 초기 cohort |
|---|---|---|---|---|---|---:|
| C4800 | `g2-submit-3_model_4800.pt` | `ea93f9b5…bfaba65` | COMPLETE, full | `806d7e82…145ad` | 4201,4202,4203 / 128 | 3,456 |
| C7050 | `model_7050.pt` | `d40f2666…188015` | COMPLETE, full | 동일 | 동일 | 3,456 |
| C7450 | `model_7450.pt` | `b8766030…82343a` | COMPLETE, full | 동일 | 동일 | 3,456 |

직접 확인한 연결은 각 ZIP의 `source_checkpoint.txt` ↔ `evaluation/evaluation_manifest.json: policy.sha256` ↔ `evaluation/video_evaluation_link.json: source_checkpoint_sha256`가 서로 일치한다는 수준이다. **원 checkpoint 파일 자체는 ZIP에 들어 있지 않으므로 원본 checkpoint bytes를 다시 hash한 검증은 아니다.** `preset`과 `source_run_id`는 세 manifest 모두 `null`이므로 학습 Run ID, fresh/resume, 부모 checkpoint를 추정하지 않았다.

평가는 세 정책 모두 `go2`, `Quadruped-v0`, deterministic inference, camera off, `scenario7/internal-suite-v1`, 20초 time-window, 128 env, seeds 4201–4203이다. `evaluation/resolved_configs.json`은 세 ZIP에서 byte-for-byte 같은 SHA-256(`e88840f4…3ef9`)이고, evaluator source fingerprints·agent config fingerprint·protocol ID도 동일하다. 따라서 **정량 원자료는 직접 A/B/C 비교 가능**하다.

영상도 모두 seed 42, 1 env, 20초/1000 step, 동일 `maneuver_push` command trace와 terrain 설정을 사용한다. 여섯 MP4의 SHA256SUMS는 세 ZIP 모두 실제 파일과 일치했다. 다만 C7050의 video `suite_driver_sha256`/`launcher_sha256`은 C4800·C7450과 다르다. task repo commit, scenario hash, command trace hash, Isaac Lab commit은 같으므로 행동 조건은 맞지만, **영상 캡처 도구 자체는 세 정책 모두 byte-identical하지 않다.** 정량 evaluator 쪽에는 이 차이가 없다.

### 평가 case

- G1 `flat`: 1.0→1.5 m/s 전진 추종
- G2 `mixed`: 횡이동·yaw를 포함한 전방위 추종
- G3 `rough`: random rough, 전진 1.0
- G4 `slope_up`, `slope_down`: 20° 설정
- G5 `stairs_up`, `stairs_down`: step height 0.125
- G6 `push`: 고정 외란 schedule
- G7 `randomized`: rough + friction/base-mass randomization

전체 9 case × 3 seed × 128 env = **3,456 cohort**다. reset이 없으면 cohort당 episode 1개지만 종료 후 time-window 잔여 구간이 새 episode로 이어지므로 raw episode 수는 C4800 3,471, C7050 3,458, C7450 3,460이다. episode ID 중복은 없었다.

## 3. 정량 비교 — 추종, 진행, 실패와 trade-off

### 3.1 case별 핵심 결과

아래 값은 `evaluation/episodes.jsonl`을 직접 재집계한 **episode 행 기준 평균**이다. 표 셀은 `mean_tracking_error / forward_progress_m / episode survival` 순서다. `mean_tracking_error`는 혼합 단위 내부 지표이므로 단일 물리 단위를 붙이지 않는다. `forward_progress_m`은 `integrated_body_forward_m`와 동일 필드이므로 하나의 근거로만 사용한다.

| scenario / case | C4800 | C7050 | C7450 |
|---|---:|---:|---:|
| G1 flat | **0.079 / 25.07 / 100%** | 0.086 / 24.52 / 100% | 0.086 / 24.87 / 100% |
| G2 mixed | 0.091 / 11.91 / 100% | 0.081 / **12.12** / 100% | **0.077** / 12.09 / 100% |
| G3 rough | **0.088** / 19.95 / 100% | 0.097 / 19.67 / 100% | 0.091 / **20.00** / 100% |
| G4 slope up | 0.113 / 20.02 / 100% | 0.111 / 19.52 / 100% | **0.107** / 19.90 / 100% |
| G4 slope down | 0.116 / **20.17** / 100% | 0.114 / 19.64 / 100% | **0.109** / 19.94 / 100% |
| G5 stairs up | 0.282 / 15.98 / 97.96% | 0.168 / 18.67 / **99.48%** | **0.156** / **19.00** / 98.97% |
| G5 stairs down | 0.359 / 14.67 / 98.21% | 0.174 / 18.89 / **100%** | **0.141** / **19.76** / **100%** |
| G6 push | **0.094** / 20.07 / 100% | 0.105 / 19.69 / 100% | 0.100 / **20.04** / 100% |
| G7 randomized | **0.087** / 19.97 / 100% | 0.097 / 19.67 / 100% | 0.090 / **20.00** / 100% |

**중요한 패턴:**

1. **C4800의 실패는 계단에 국소화되지만 크다.** 비계단 7개 case에서는 종료가 0이고 G1/G3/G6/G7 tracking은 오히려 세 정책 중 가장 낮다. 그러나 stairs_down/up에서 tracking `0.359/0.282`, 진행 `14.67/15.98 m`, stall `10.74%/6.98%`로 급격히 악화한다.
2. **C7050→C7450은 대체로 추종·진행 개선이다.** C7450은 C7050 대비 9개 case 중 8개에서 tracking error가 낮고(flat만 +0.00031), 8개에서 진행이 크다(mixed만 -0.034 m). 특히 stairs_down은 tracking `0.174→0.141`, 진행 `18.89→19.76 m`, stall `2.52%→0.60%`다.
3. C7450이 C4800의 모든 장점을 지운 것은 아니다. C4800은 G1/G3/G6/G7에서 평균 tracking이 더 낮고, slope-down의 평균 body-forward 적분도 약간 더 크다. 따라서 “iteration 숫자가 큰 정책이 전 축에서 단조 개선”이라는 해석은 성립하지 않는다.

### 3.2 고정 20초 cohort 실패 — episode survival과 분리

`survived=false`를 전부 낙상으로 부르지 않고 `end_reason`과 `base_contact_failure`를 확인했다. 이번 자료의 모든 `terminated` episode는 `base_contact_failure=true`였고, 그 외 case에는 terminated가 없다.

| case | C4800: 20초 창 내 한 번이라도 terminated | C7050 | C7450 |
|---|---:|---:|---:|
| stairs_up | 8 / 384 = **2.08%** | 2 / 384 = **0.52%** | 4 / 384 = **1.04%** |
| stairs_down | 7 / 384 = **1.82%** | 0 / 384 | 0 / 384 |
| 나머지 7 case | 0 / 2,688 | 0 / 2,688 | 0 / 2,688 |

한 cohort에서 2회 이상 terminated된 경우는 없었다. C4800은 stairs-up 실패가 seeds 4201/4202/4203에 `2/4/2`, stairs-down이 `0/3/4`로 여러 seed에 퍼진다. 반면 C7050의 2회와 C7450의 4회는 모두 **stairs_up, seed 4201**에만 있다. 이는 C7450의 생존 열화가 broad collapse보다는 특정 seed/초기조건에 집중된 약점임을 보여준다.

동시에 seed별 stairs-up 평균 tracking은 C7050 `0.173 / 0.166 / 0.166`, C7450 `0.161 / 0.154 / 0.151`로 **세 seed 모두 C7450이 낮다.** 즉 C7450의 추가 종료 2회 때문에 전반적인 stair-up 추종 개선이 사라지는 것은 아니다.

### 3.3 평균만으로 숨겨지는 계단 tail

95% tracking error와 5% 진행 하위꼬리도 같은 방향이다.

| case | 지표 | C4800 | C7050 | C7450 |
|---|---|---:|---:|---:|
| stairs_down | tracking p95 | **0.911** | 0.238 | **0.169** |
| stairs_up | tracking p95 | **0.729** | 0.243 | **0.222** |
| stairs_down | progress p05 (m) | **2.10** | 17.86 | **19.47** |
| stairs_up | progress p05 (m) | **6.12** | 17.18 | **17.68** |

C4800의 계단 평균 저하는 소수 극단점만의 문제가 아니다. p95 tracking과 progress 하위꼬리가 모두 크게 무너진다. 반대로 C7450은 C7050보다 stair-down tail까지 명확히 개선한다.

### 3.4 자세·행동 비용: C7450의 명확한 대가

9개 case의 case-동일가중 보조 평균(성능 점수가 아니라 trade-off 요약)은 다음과 같다.

| 지표 | C4800 | C7050 | C7450 | 해석 |
|---|---:|---:|---:|---|
| mean tracking error | 0.1455 | 0.1147 | **0.1064** | C7450 우위 |
| forward progress (m) | 18.65 | 19.15 | **19.51** | C7450 우위 |
| stall fraction | 2.23% | 0.67% | **0.51%** | C7450 우위 |
| roll_pitch_rms | **0.1409** | 0.1419 | **0.1537** | C7450 불리 |
| action_delta_rms | 0.3934 | **0.3838** | **0.4114** | C7050 가장 부드러움 |

C7450은 C7050 대비 `action_delta_rms`가 약 7% 높고 `roll_pitch_rms`도 약 8% 높다. 이는 측정된 실제 trade-off다. 관절 토크, foot sliding, foot air time, joint deviation은 이 evaluator에 없으므로 해당 정량값을 만들지 않았다.

C4800은 비계단에서 낮은 roll/pitch와 좋은 일부 tracking을 보이지만, 계단 접촉 시 그 안정성이 유지되지 않는다. 따라서 낮은 비계단 자세 RMS를 전체 안정성 우위로 확대하면 안 된다.

## 4. 여섯 지형 영상 — 실제 행동과 정량 결과 연결

### 확인 방법과 capture 상태

각 정책의 여섯 MP4, 총 18개를 실제 디코드해 20초 전체를 1초 간격 프레임 시퀀스로 조사했다. stairs 초기 0–8초는 0.5초 간격으로, random rough의 4/8/12/16초 push 주변은 0.2초 간격으로 추가 확인했다. 따라서 아래는 단일 스틸 한 장이 아니라 시간 순서 프레임 조사에 근거하지만, full-rate 50 fps 동작을 사람 눈으로 연속 재생한 것과 동일한 수준의 미세 foot-slip 판정은 아니다.

`blackdetect`에서는 모든 MP4 시작의 20 ms 검정 초기 프레임이 잡혔고, C4800 `03_boxes.mp4`와 C7450 `06_slope_down_20deg.mp4`에는 0.04–0.06 s에 추가 20 ms black frame이 하나씩 있었다. 이후 반복적인 black/valid 교대는 검출되지 않았다. **정책 실패가 아닌 capture 초기화 artifact로 제외했다.**

영상 command는 전역 시간표다: 0–6 s 전진, 6–10 s `vy=+0.3`, 10–14 s `vy=-0.3`, 14–17 s `yaw=+0.5`, 17–20 s `yaw=-0.5`; world-Y push는 4/8/12/16 s다. evaluator는 별도 camera-off 실행이므로 영상과 수치를 동일 episode 재측정으로 취급하지 않는다.

### `01_stairs.mp4`

- 세 정책 모두 0–4초에 계단 경계 쪽으로 계속 이동하고, 약 4–8초 구간에서 stepped region의 경계가 카메라 뒤쪽으로 빠지면서 이동을 지속한다. dense frame에서 push 직후에도 넘어지거나 reset되는 장면은 없다.
- C4800도 이 **단일 seed=42 영상**에서는 20초 생존한다. 이는 camera-off G5에서 보인 1.8–2.1% cohort 실패와 모순이 아니다. 영상 한 env가 희귀 실패를 대표할 수 없기 때문이다.
- C7050과 C7450의 시각 차이는 크지 않다. 정량 evaluator가 보여주는 C7450의 계단 progress/stall 이득이 더 신뢰할 만한 비교 근거다.

### `02_inverted_stairs.mp4`

- C4800과 C7450은 초반 striped stair 영역에서 빠르게 멀어지고 이후 평지에서 command 변경을 수행한다.
- C7050은 stair 경계가 더 오래 화면에 남고 14초 이후 yaw command 구간에서 다시 경계 쪽으로 접근한다. 1초 프레임만 보면 정체처럼 보일 수 있으나, 14–20초는 회전 명령 구간이고 로봇의 heading marker가 실제로 회전하며 위치도 계속 변한다. **stall로 판정할 근거는 없다.**
- 이 영상에서 세 정책 모두 전복/접촉 종료는 보이지 않는다.

### `03_boxes.mp4`

- 세 정책 모두 초반 boxes 영역을 통과해 약 8–9초 이후 장애물 군집이 화면에서 사라지고 평지 이동을 이어간다.
- 큰 정체나 전복은 보이지 않는다. C7450의 더 높은 `action_delta_rms`가 이 1초 시퀀스에서 명백한 hopping으로 나타난다고 말할 정도의 시각 근거는 없다.

### `04_random_rough.mp4`

- 세 정책 모두 rough patch에서 실제 위치가 변하고 약 8–9초 이후 patch를 벗어나 계속 이동한다. 단순히 카메라 중앙에 서 있는 패턴은 아니다.
- 4/8/12/16초 push 전후를 0.2초 간격으로 추가 조사했을 때 세 정책 모두 push 뒤에도 자세를 잃고 장시간 멈추거나 reset되는 장면 없이 보행을 계속한다.
- 정량 G3/G7에서는 C4800의 평균 tracking이 가장 낮고, C7450이 C7050보다 진행·tracking을 개선한다. 영상은 세 정책 모두 “실제로 움직인다”는 점을 확인하지만 이 작은 수치 차이를 시각만으로 순위화하지 않는다.

### `05_slope_up_20deg.mp4` / `06_slope_down_20deg.mp4`

- 세 정책 모두 20° slope patch에서 위치를 바꾸며 20초를 버티고, 초반 경사 영역을 지나 이후 평지에서 횡이동·회전 command를 수행한다. 영상상 명백한 전복/리셋은 없다.
- camera-off G4에서도 세 정책 모두 768 episode(두 case 합산)에서 terminated 0이다.
- 추종은 C7450이 slope_up/down 모두 가장 낮은 평균 error를 보인다(`0.107/0.109`). C4800은 slope-down forward integral이 약간 더 크지만 tracking error는 더 크다. 따라서 “빨리 움직이는 것”과 “명령을 더 정확히 따르는 것”의 작은 trade-off가 있다.

### 영상과 평가를 합친 행동 판단

세 정책 모두 **생존만 하는 정지 정책은 아니다.** 영상에서 장애 지형이 상대적으로 뒤로 빠지고 command 변경 이후 heading/trajectory가 바뀌며, camera-off evaluator에서도 19–25 m 수준의 body-frame 진행과 낮은 stall을 기록한다(C4800 계단 제외). push 뒤에도 단일 영상에서는 이동을 재개한다.

핵심 실패 양상은 영상에서 자주 보이는 상시 붕괴가 아니라 **다수 env 평가에서 드러나는 계단 접촉의 낮은 확률 tail**이다. C4800은 그 tail이 여러 seed와 상·하행에 퍼져 있고, C7050/C7450은 stair-up seed 4201에만 남는다.

## 5. 종합 판단 — 좋은 방향인가?

### C7450: PROMOTE

목표 행동을 실제로 수행한다. 평지·전방위·rough·경사·계단·push/randomization 모두에서 진행이 있고, stall은 낮으며, 종료는 3,456 cohort 중 stair-up 4개에만 있다. 특히 C7050 대비 계단 하행의 추종·진행·stall 개선이 크고, 개선이 평균뿐 아니라 tracking p95와 progress p05에도 나타난다.

가장 큰 약점은 **제어가 더 거칠어진 것**이다. action 변화와 body roll/pitch RMS가 올라갔고 stair-up 종료가 2→4개로 증가했다. 따라서 “안정성까지 전부 좋아졌다”는 결론은 아니다. 그러나 현재 evidence에서 이 비용은 C7450을 HOLD로 내릴 정도로 광범위하지 않으며, 실제 진행/추종 이득이 더 넓고 크다.

### C7050: HOLD

행동 품질이 나쁜 정책이 아니다. 오히려 현재 세 후보 중 가장 낮은 action 변화량과 가장 적은 terminated 수를 보여 **안전성 중심 후보**로 강하다. 하지만 C7450과 비교하면 계단 하행 stall과 tracking/progress가 뚜렷하게 뒤지고, rough/slope/push/randomized도 대체로 소폭 뒤진다. 따라서 현재 주 후보보다는 fallback이 적절하다.

### C4800: REJECT for all-around candidate

평지와 rough 계열 추종 자체는 강점이다. 하지만 계단 성능은 경쟁 후보와 질적으로 다른 수준의 약점이다. 다수 seed에서 base-contact 종료가 발생하고, 진행 하위 5%가 stairs-down 약 2.1 m까지 무너지며, stall과 tracking tail도 크다. 계단을 제외한 특수 목적 정책이라면 다시 볼 수 있지만, 현재 목표 범위에서는 채택하지 않는 것이 맞다.

### reward/학습 방향에 대해 말할 수 없는 것

이 ZIP만으로는 세 checkpoint의 training reward 차이, 학습량 관계, 부모/resume 계보를 검증할 수 없다. 따라서 **C7050→C7450의 행동 차이를 특정 reward 변경이나 추가 학습의 인과효과로 해석하지 않는다.** 여기서 PROMOTE/HOLD/REJECT는 오직 이번 정책 후보의 행동 evidence 판정이다.

## 6. 다음 행동 한 가지와 재확인 가능한 근거

### 다음 행동: **C7450을 현재 Go2 내부 주 후보로 승격하고, C7050을 안전성 fallback으로 보존한다.**

이번 원자료만으로 후보 선택 질문은 충분히 답할 수 있으므로 새 학습이나 새 full 평가를 기본 다음 단계로 요구하지 않는다. 실제 제출/최종 고정 직전에 추가 GPU evidence가 필요해지는 경우에만, 판단을 바꿀 수 있는 유일하게 중요한 불확실성은 **C7050(2회)과 C7450(4회)의 stair-up 종료 차이가 seed 4201 특이 현상인지 재현되는지**다. 그때는 다른 reward를 건드리기보다 동일 protocol의 stair-up 추가 seed/반복이 정보가치가 높다. 현재 요청에서는 실행하지 않았다.

### 재확인 가능한 ZIP 내부 근거

각 ZIP에서 다음만 보면 이 보고서의 핵심을 재현할 수 있다.

- `source_checkpoint.txt` — checkpoint 이름·기록 SHA
- `environment.txt`, `README.txt` — 영상 task/seed/20초 command·push schedule, terrain 조건
- `SHA256SUMS.txt` — 6 MP4 무결성
- `evaluation/evaluation_manifest.json` — complete/smoke, policy SHA, protocol, seed/env, source fingerprint, scenario/case 정의
- `evaluation/resolved_configs.json` — 실제 적용 평가 설정; 세 ZIP byte-identical
- `evaluation/episodes.jsonl` — 본 보고서의 정량 재집계 원자료
- `evaluation/diagnostics.json` — scenario별 제공 요약과 재집계 교차 확인
- `evaluation/video_evaluation_link.json` — 영상 source checkpoint와 평가 policy SHA 연결
- `evaluation/evaluation.log` — 세 실행 모두 child exit 0 / COMPLETE 확인
- 루트 `01_stairs.mp4` … `06_slope_down_20deg.mp4` — 정성 행동 확인

### 직접 검증 요약

- 세 평가: `complete=true`, `smoke=false`, child exit 0
- initial cohorts: 정책별 3,456
- raw episode ID 중복: 0
- `diagnostics.json`의 scenario episode 수·survival·mean tracking은 raw 재집계와 일치
- 18개 MP4: ZIP 내부 `SHA256SUMS.txt` 검증 PASS
- video↔evaluation checkpoint SHA metadata 일치
- 원 checkpoint 자체는 ZIP 미포함: SHA 연결은 metadata provenance이며 원본 bytes 독립 재검증은 아님
