# 공개 관리 원칙

## 원본 구조·내용 보존

기존 저장소 이름을 최상위 폴더로 사용하고, 그 아래 원래 상대 경로를 유지합니다. 원본 파일을 다시 해석하거나 요약하지 않습니다. 제목, 파일명, 본문, 코드, 수치, 결론, 상태, Run ID, 해시, 링크, 줄바꿈과 Markdown 공백도 원본대로 둡니다.

공개 안내·보존 한계·출처·제외 이유는 이 `_publication` 폴더에서만 관리합니다. 과거 문서의 권고나 상태는 당시 기록이며 최신 실행 지침으로 일괄 승격하지 않습니다. 원래 파일 안의 내부·비공개 링크나 제외 파일 참조는 고치지 않고 별도 [참조 누락 목록](MISSING_REFERENCES.json)에 기록합니다.

## 블라인드와 제외

- 개인 Windows 프로필의 계정명만 `C:/Users/[USER]`로 블라인드합니다. 파일별 원본/공개 SHA와 변환 여부는 [FILES.json](FILES.json)에 있습니다.
- 개인정보·비밀정보 외에 단지 경로·Run ID·checkpoint SHA·자체 점수라는 이유로 가리지 않습니다.
- 원문 전사나 제공 소스를 포함해 부분 편집이 필요한 파일은 통째로 제외합니다. 제외한 파일의 대체 요약을 원문인 것처럼 쓰지 않습니다.
- 공식 training·강의·실습·대화 원문·모델·전체 training archive는 이번 선별 범위에 없습니다. 원본 보존소에서 삭제하지 않습니다.
- 로컬 전용 `AGENTS.md`/`AGENTS.disabled.md`는 업로드하지 않습니다.

## Release 보존

[RELEASES.json](RELEASES.json)이 원래 저장소·tag·제목·본문 SHA·asset 이름·원본/공개 SHA를 연결합니다. 공개 tag의 `eval--` 접두어는 원래 저장소 구분용이며 새 실험 ID가 아닙니다. 각 Release의 공개 안내 뒤 원래 본문은 그대로입니다.

ZIP도 원래 파일명·멤버 이름·순서·구성을 유지합니다. 로그나 기존 checksum 파일을 빼지 않습니다. 개인정보가 없다면 ZIP 자체를 바이트 동일하게 복사합니다. 블라인드가 필요한 경우 해당 텍스트의 개인 프로필 부분만 바꾸며 영상·episode 원자료는 바이트 동일하게 보존합니다. ZIP 안의 기존 checksum은 원본 자료 기준이므로 블라인드한 파일에는 맞지 않을 수 있습니다. 공개 asset의 정확한 SHA는 위 manifest를 사용합니다.

전체 preset YAML, 외부 task 및 원본 archive는 빠져 있으므로 문서에 full resolved config가 보존됐다고 적혀 있어도 이 공개 snapshot에 그 payload까지 있다는 뜻은 아닙니다. `null` 계보나 실패 기록을 사후에 수정하거나 verified 상태로 만들지 않습니다.

## 이전 공개 방식과의 차이

이전 commit `1c3fa3e`는 기능별 폴더와 파생 문서 안내·링크 정리를 사용했습니다. 현재 방식은 원본 저장소별 배치와 블라인드만 적용합니다. 이전 파일·묶음 Release는 Git 이력과 기존 snapshot에 보존되며 원본 저장소는 그대로입니다.

라이선스는 미정입니다. 선별 검토는 모든 원본 자료나 법적 권리를 보증하는 전면 검사가 아닙니다.
