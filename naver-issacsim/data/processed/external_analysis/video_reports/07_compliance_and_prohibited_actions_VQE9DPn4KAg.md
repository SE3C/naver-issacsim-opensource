## 0. 먼저 읽어야 할 핵심 결론

이 영상의 메시지는 단순한 “부정행위 금지 공지”가 아니다. 전체 구조는 다음 한 줄로 요약할 수 있다.

> **도구는 넓게 허용하지만, 제출 정책은 공식 제공 환경에서 직접 만들어야 하며, 무엇을 왜 했는지를 팀이 설명하고 책임질 수 있어야 한다.**

영상에서 반복되는 핵심선은 다음과 같다.

1. **제출용 정책을 만드는 학습은 제공 서버에서 해야 한다.**
2. **개인·학교 PC에서는 만들어진 정책을 실행·관찰·검토하는 것은 가능하다.**
3. **논문·공개 저장소·LLM·Copilot·AI 튜터·직접 작성한 자동화 스크립트 등은 활용 가능하다.**
4. **다른 팀의 정책/보상 설정을 공유받거나, 제3자가 대신 학습하거나, 외부 GPU에서 학습한 정책을 제출하는 것은 금지된다.**
5. **제공 서버에 새 에이전트/도구를 설치하여 환경을 바꾸는 행동은 금지된다.**
6. **학습과 서버 활동에는 기록이 남으며, 제출물은 서버의 학습 기록과 대조될 수 있다.**
7. **AI 사용 자체보다 중요한 것은 설명 가능성이다. AI가 답을 만들어 줄 수 있어도 그 답의 책임은 참가자가 진다.**
8. **평가는 결과만 보는 것이 아니라 의도와 설명도 본다.**
9. **공정성 문제는 한 팀의 순위만이 아니라, 장비가 돌아갈 학교와 다음 학생들에게도 영향을 준다.**
10. **운영진이 원하는 참가자는 “가장 빨리 정답을 복제한 팀”이 아니라, 이 분야를 계속 이어갈 수 있는 사람이라는 철학으로 영상이 마무리된다.**

# 3. 00:20~00:50 — 참가자에게 제공되는 기본 환경

영상은 대회가 참가자에게 이미 상당한 도구와 인프라를 제공한다는 점을 먼저 보여준다.

화면에 나타나는 4개 카드:

### 3.1 팀마다 분리된 서버

> **팀마다 분리된 서버**  
> GPU 서버와 **100시간**을 팀별로

의미:

- 각 팀은 분리된 GPU 서버 환경을 사용한다.
- 100시간은 핵심 제한 자원이다.
- 이 구조는 공정성·학습 기록·제출물 추적의 기반이 된다.

현재 통합 규정과도 일치한다. 현재 규정 정리에서는 예선 서버 시간이 팀 전체 합산 100시간이며 라운드별로 초기화되지 않는 것으로 정리되어 있다.

### 3.2 미리 설치된 학습 환경

> **미리 설치된 학습 환경**  
> 설정 없이 바로 시작

의미:

- 참가자가 임의로 환경을 재구축하기보다 운영진이 제공한 기준 환경을 사용하도록 설계되었다.
- 뒤에서 나오는 “서버 내부에 새 도구를 설치하지 말라”는 내용과 연결된다.

### 3.3 가이드북

> **가이드북**  
> 처음부터 끝까지 따라갈 수 있게

단순히 환경만 주는 것이 아니라 공식 학습 절차와 참고 자료도 제공된다는 메시지다.

### 3.4 AI 튜터

> **AI 튜터**  
> 언제든 물어볼 수 있게

AI 자체를 금지하는 대회가 아니라는 점을 초반부터 명확히 한다. 후반부에서 LLM/Copilot 사용을 자유롭게 허용한다고 다시 강조한다.

# 4. 00:50~01:45 — “이 대회의 상은 조금 특별합니다”

화면 제목:

> **이 대회의 상은 조금 특별합니다**

## 4.1 AI 연구 스테이션은 개인 상품이 아니다

화면에서는 다음 구조를 제시한다.

```text
AI 연구 스테이션
수상 팀에게 가는 것이 아니라
        ↓
그 팀이 속한 학교로
다음 학생들에게 남도록
```

즉 장비는 참가 학생 개인이나 팀이 가져가는 상이라기보다, **학교에 남아 다음 학생들이 사용할 연구 자산**으로 설계되어 있다.

## 4.2 한 학교가 받을 수 있는 수량에는 상한이 있음

화면 문구:

> **한 학교가 받을 수 있는 수량에는 상한이 있습니다 — 잘해도 더 가져가지 않습니다**

이후 학교 아이콘 01~08이 등장하며:

> **남은 장비는 총 여덟 개 학교가 받을 때까지 이어집니다**

라는 구조를 보여준다.

핵심 의미:

- 단순 상위 팀 독식 구조가 아니다.
- 순위 하나의 변화가 단지 한 팀의 등수 변화로 끝나지 않을 수 있다.
- 학교 단위 장비 배분과 다음 학생들의 기회까지 연결된다.

## 4.3 공정성은 ‘우리 팀만의 문제’가 아니다

예시 순위표가 등장한다.

```text
1위 --- 182
2위 --- 176
3위 --- 171
4위 --- 168
5위 --- 165
```

오른쪽에는 “순위와 함께 움직이는 것”으로 학교 아이콘이 제시된다.

화면 문구:

> **순위 하나가 흔들리면, 한 팀의 등수만 바뀌는 게 아닙니다.**  
> **다른 학교의 후배들이 쓰게 될 장비가 함께 움직입니다.**

그리고 핵심 문장:

> **그래서 공정함은, 우리 팀만의 문제가 아닙니다**

이 영상이 금지행위를 다루는 방식의 출발점이다. 규칙 준수를 “걸리면 벌 받는다”가 아니라 **기회의 배분을 왜곡하지 말아야 한다**는 문제로 설명한다.

# 5. 01:45~02:30 — 학습과 서버 활동에는 기록이 남는다

## 5.1 학습이 끝나면 기록이 남는다

화면 제목:

> **학습이 끝나면 기록이 남습니다**

왼쪽:

```text
✅ 학습 완료
여러분의 서버에서
```

오른쪽:

```text
대회 서버 · 학습 기록
config   어떤 설정으로 학습했는지
```

의미:

- 단순히 최종 `policy.pt`만 존재하는 구조가 아니다.
- 어떤 설정으로 학습했는지 기록이 연결된다.
- 제출물의 출처와 학습 이력 검증이 가능하다는 점을 시각적으로 설명한다.

## 5.2 서버에서 한 일도 시스템에 남는다

화면 제목:

> **서버에서 한 일도 시스템에 남습니다**

예시 활동 로그:

```text
10:04:12   세션 시작      s-2026-ab001
10:41:55   학습 실행      run #128 · H1
13:22:07   결과 전송      학습 산출물 일체
13:25:40   세션 종료      GPU 2h 18m · 누적 31h / 100h
14:07:31   시스템 감지    학습 환경 변경 시도 · 도구 설치
```

중요한 점:

- 세션 시작/종료
- 학습 실행
- 결과 전송
- GPU 사용 시간
- 누적 100시간 사용량
- 환경 변경/도구 설치 시도

같은 이벤트가 기록되는 예시를 보여준다.

이것은 참가자에게 **“환경을 임의로 바꿔도 확인할 수 없다”는 전제로 행동하지 말라**는 경고다.

# 6. 02:30~02:55 — “학습된 정책에는 지문이 있습니다”

화면 제목:

> **학습된 정책에는 지문이 있습니다**

상단 조건:

> **같은 설정 · same config · same seed**

아래에는 `policy_A`와 `policy_B`가 서로 다른 형태의 지문 그래픽으로 나타난다.

가운데:

> `≠`

하단 문구:

> **강화학습은 매번 다른 길로 답을 찾아가기 때문입니다**

## 6.1 이 문장의 기술적 의미

영상은 동일한 config와 seed를 쓰더라도 강화학습의 실제 결과 정책이 항상 완전히 동일한 결과물로 귀결되는 것은 아니라는 점을 참가자용 비유로 설명한다.

여기서 “지문”은 실제 암호학적 fingerprint나 특정 파일 해시만을 의미한다고 단정하면 안 된다. 영상의 의도는 다음에 가깝다.

- 학습 결과에는 학습 과정의 특성이 남는다.
- 남의 정책 파일을 그대로 가져오면 서버 기록과 연결이 어긋날 수 있다.
- 제출 정책과 공식 학습 이력을 함께 보면 부정한 출처를 판단할 수 있다.

## 6.2 심사 시 대조

다음 화면:

> **심사할 때는 이렇게 맞춰봅니다**

왼쪽 제출물:

```text
제출물
policy.pt
reward · config
```

오른쪽 서버 학습 기록:

```text
서버의 학습 기록
run log
checkpoint
```

즉 제출된 정책/보상 설정과 서버에 남은 학습 실행·체크포인트 기록을 대조한다는 메시지다.

# 7. 02:55~03:35 — 허용되는 도구와 연구 방식

영상 제목:

> **이런 건 모두 괜찮습니다**

화면에 단계적으로 5개 질문이 나온다.

## 7.1 논문이나 공개 저장소의 값을 참고해도 되나요?

> **됩니다**

즉 공개된 연구 결과나 공개 저장소를 참고해 reward 값, 설계 아이디어 등을 얻는 것 자체는 금지하지 않는다.

## 7.2 LLM이나 코파일럿을 써도 되나요?

> **자유롭게**

AI 도구 사용 자체를 제한하지 않는다는 매우 명시적인 장면이다.

## 7.3 결과물을 개인·학교 PC에서 돌려봐도 되나요?

> **됩니다**

이 장면은 현재 프로젝트의 개인 NVIDIA 서버 활용 전략과 매우 중요하게 연결된다.

허용되는 방향:

```text
공식 서버에서 생성한 결과물
        ↓
```

이 영상은 금지사항을 겁주는 방식으로 끝내지 않고, **공정한 경쟁 → 실제 실력 → 학교와 후배에게 남는 자산**이라는 이야기로 끝난다.

# 18. 우리 프로젝트에 직접 영향을 주는 해석

## 18.1 개인 NVIDIA 서버는 ‘검증 서버’로 사용

현재 프로젝트에서 계획한 개인 NVIDIA 서버의 가장 안전한 역할은 영상과 완전히 일치한다.

```text
공식 서버
reward 수정
→ 학습
→ policy.pt / env.yaml 생성
        ↓
개인 NVIDIA 서버
→ policy 실행
→ play / 시나리오 반복
→ 속도 추종/낙상/회복 분석
→ 영상/로그 저장
→ 다음 reward 후보 결정
        ↓
공식 서버
→ 다음 reward 학습
```

반대로 다음 흐름은 금지선이다.

```text
개인 NVIDIA 서버에서 policy 새로 학습
        ↓
그 policy.pt를 대회 제출
```

## 18.2 Optuna는 “정책 생성 엔진”이 아니라 “후보 추천 도구”로 써야 안전

영상은 LLM에게 다음 값을 묻거나 자동화 스크립트를 사용하는 것을 허용한다.

따라서 Optuna도 규정 친화적으로 쓰려면:

```text
개인 PC/개인 서버
- 기존 공식 실험 결과 정리
- trial DB
- 다음 reward 후보 추천

공식 서버
- 추천받은 reward 값 반영
- 실제 제출 정책 학습
```

형태가 안전하다.

개인 서버 Optuna가 직접 외부 GPU 학습을 돌려 만들어낸 정책을 제출하는 구조는 피해야 한다.

## 18.3 실험 로그를 반드시 남겨야 함

영상 후반 평가 구조상 팀 내부에서도 최소한 다음을 기록하는 것이 좋다.

```text
실험 ID
로봇: H1 / Go2
변경 reward
기존 값 → 새 값
왜 바꿨는지
예상한 행동 변화
학습 실행 시간
seed / iterations
핵심 지표
play 관찰
실패 원인
다음 실험
정책 파일 식별자
env.yaml 식별자
```

이 기록은 점수를 잘 받기 위한 자료이면서 동시에 “우리가 왜 이 값을 썼는지” 설명하는 근거가 된다.

## 18.4 AI에게 물어볼 때도 설명 가능한 형태로

좋은 사용:

```text
현재 H1이 lateral command에서 흔들린다.
현재 reward는 A/B/C다.
영상에서 이런 실패가 관찰된다.
한 번에 하나만 바꾼다면 어떤 항목을 먼저 실험할까?
```

나쁜 사용:

```text
최고점 나오는 값 아무거나 줘
→ 그대로 입력
→ 왜 썼는지 모름
```

영상이 요구하는 것은 AI 비사용이 아니라 **의도·근거·결과를 연결할 수 있는 연구 과정**이다.

# 19. 영상 ↔ 2026 통합 규정 교차검증

## 19.1 공식 서버에서 제출 정책 학습

영상:

> 제출물은 반드시 제공 서버에서 만들어야 한다.

통합 규정 정리:

- 제출 정책을 만드는 강화학습은 운영진 제공 서버에서만 수행.
- 개인·학교 PC나 외부 GPU에서 학습한 정책으로 제출하면 안 됨.

**판정: 일치**

## 19.2 개인 PC에서 결과물 실행·관찰

영상:

> 개인·학교 PC에서 만들어진 정책을 실행하고 관찰 가능. `play.py`, 결과 확인, 영상 보기, 파일 점검.

통합 규정 정리:

- 공식 서버에서 생성된 결과물을 개인 PC로 내려받아 실행·관찰·영상 확인 가능.

**판정: 일치**

## 19.3 LLM/Copilot

영상:

> LLM이나 Copilot 사용 “자유롭게”.

통합 규정 정리:

- LLM·Copilot 등 AI 도구 사용 자체는 제한하지 않음.
- 최종 책임은 팀에 있음.

**판정: 일치**

## 19.4 서버 환경 변경

영상:

> 서버 안에 새 도구 설치 금지. 제공 서버는 받은 그대로 사용.

통합 규정 정리:

- 제공 GPU 서버에 MCP·에이전트·외부 연결을 설치하거나 환경을 변경하지 않음.

**판정: 일치**

## 19.5 타 팀과 정책/설정 공유

영상:

> 다른 팀과 정책 파일이나 보상 설정을 주고받는 것 금지.

통합 규정 정리:

- 다른 팀과 정책·설정·결과물을 공유하거나 공동 제출하는 행위 금지.

**판정: 일치**

## 19.6 제재 3년

영상:

> 경고 → 경기 참여 기회 박탈 → 수상 취소. 중대 위반 즉시 실격 가능. 이후 3년 재단 행사 참가 제한.

통합 규정 정리:

- 위반 시 경고·실격·수상 취소와 향후 3년 재단 행사 참여 제한 가능.

**판정: 일치**

## 19.7 평가 70/20/10

영상:

```text
자동 평가 70
의도 분석 20
설명 10
```

통합 규정 정리:

```text
시뮬레이션 성능 70
보상 변경 의도와 env.yaml 일치 20
기술 개선 리포트 10
```

**판정: 큰 틀에서 일치**

영상은 대중적인 표현으로 “의도 분석/설명”이라고 표시하고, 통합 규정은 이를 보다 구체적으로 `env.yaml` 일치와 기술 개선 리포트로 정의한다.

# 20. 기존 OT 분석과의 교차검증

기존 OT 통합 분석에서도 다음 내용이 확인되어 있다.

- 팀 전체 예선 서버 시간 100시간
- 외부 LLM/Copilot은 개인 PC에서 분석·코딩 보조로 활용 가능
- 제출 정책의 학습은 공식 제공 환경에서 수행
- 제공 GPU 서버에 MCP·외부 에이전트·임의 설치·환경 변경을 하지 않음
- 개인 PC에서 결과를 관찰·테스트하는 것과 외부 GPU 학습 정책을 제출하는 것은 다름
- private GitHub 자체보다 타 팀 공유/공개 유출이 문제

이번 준수사항 영상은 이 OT 안내를 훨씬 더 명확한 규칙/철학 형태로 압축해서 보여준다.

즉 이번 영상은 새로운 학습 튜토리얼이라기보다:

```text
OT에서 설명한 운영 원칙
        +
통합 규정의 금지선
        +
예선 평가의 설명 가능성
        +
학교/후배에게 돌아가는 장비의 공정성
```

을 하나의 짧은 윤리·운영 영상으로 만든 것으로 볼 수 있다.

# 22. 규정 해석상 특히 조심해야 할 부분

## 22.1 “개인 PC에서 돌려봐도 된다” ≠ “개인 PC에서 재학습해도 된다”

영상에서 허용하는 개인 PC 역할은 분명히 **만들어진 정책의 실행·관찰**이다.

따라서:

```text
policy inference / play / 영상 확인 / 로그 분석 → 가능
policy를 업데이트하는 강화학습 → 제출용으로 사용하면 금지
```

으로 구분해야 한다.

## 22.2 “도구 사용을 제한하지 않는다” ≠ “공식 서버 환경을 마음대로 바꿔도 된다”

AI, 논문, 공개 저장소, Copilot, 직접 작성 스크립트는 허용되지만 제공 서버에 새 도구/에이전트를 설치해 환경을 바꾸는 것은 별도로 금지한다.

## 22.3 “공개 값을 참고 가능” ≠ “타 팀의 비공개 reward 설정 공유 가능”

영상은 공개 자료 참고와 다른 팀의 정책/보상 설정 교환을 명확히 분리한다.

```text
공개 논문/GitHub → 참고 가능
타 참가팀의 비공개 policy/reward → 공유 금지
```

## 22.4 “AI가 작성한 코드 사용 가능” ≠ “책임을 AI에 넘길 수 있음”

운영진이 의도와 근거를 물을 수 있으므로 최종적으로 팀이 설명할 수 있어야 한다.

```text
어떤 결과가 나왔는지를
팀이 직접 설명할 수 있어야 한다.
```

대회의 공정성은 단지 순위표의 숫자 문제가 아니다. 상위 결과에 따라 연구 장비가 학교로 가고, 그 장비가 다음 학생들에게 이어지기 때문에 한 팀의 부정행위는 다른 학교의 기회까지 바꿀 수 있다는 것이 영상의 핵심 윤리적 논리다.

따라서 우리 프로젝트가 취해야 할 가장 안전하고 효율적인 운영 방식은 계속 동일하다.

```text
공식 서버 = 제출용 정책을 학습하는 곳
개인 PC/NVIDIA 서버 = 관찰·검증·분석·다음 실험 설계
AI/Optuna = 가설과 후보를 추천하는 도구
최종 판단과 설명 = 참가팀의 책임
```
