# 게임 에이전트·경로계획·관측 지도

## 제어 계층

```text
전략 텍스트 또는 규칙
→ 목표·우선순위 선택
→ GameAgent
→ PathPlanner / Grid navigation
→ waypoint
→ 속도 명령
→ 학습된 H1·Go2 정책
→ 로봇 행동·새 관측
```

고수준 전략은 “무엇을 먼저 할지”를 정하고, 저수준 정책은 “어떻게 안정적으로 움직일지”를 담당한다. 전략이 직접 관절 제어나 즉시 반사 회피를 한다고 가정하면 안 된다.

## 주요 모듈의 역할

| 모듈 | 역할 |
| --- | --- |
| `game_agent.py` | 자연어·규칙 입력을 목표 우선순위와 행동 단계로 바꾸는 상위 에이전트. |
| `path_planner.py`, `grid_nav.py` | 목표까지의 경로·우회·waypoint를 계산. |
| `observation.py` | 로봇 상태·방향·지형 정보를 정책·계획에 맞는 관측으로 변환. |
| `height_scanner.py` | 주변 지형 높이를 읽어 경로·위험 판단에 제공. |
| assets mapping | H1·Go2 에셋과 정책·수집 대상의 연결 정보를 보관. |

## 전략 설계 원칙

- LLM 없이도 동작하는 고정 규칙·휴리스틱 경로부터 만든다.
- 목표 우선순위는 큐브 가치, 거리, 위험, 차량·낙상 가능성, 남은 시간을 함께 고려한다.
- LLM 출력은 작은 구조화 결과로 제한하고, 허용된 값만 해석하도록 검증한다.
- replan은 새 목표·장애물·실패 상태가 생겼을 때만 하고, 매 프레임 LLM을 호출하는 구조를 피한다.

## 본선 전략문은 네 가지 결정을 담는다

본선 참여 안내 영상은 전략문을 다음 네 덩어리로 설명한다.

1. **우선순위**: 어떤 지형·큐브부터 노릴지
2. **포기**: 현재 정책이 불안정하거나 기대가치가 낮은 목표를 무엇에서 제외할지
3. **차량 대응**: 반사 회피 명령이 아니라 위험 구역에서 목표를 바꾸거나 건너뛸 기준
4. **대안**: 막힘이나 시간 부족 때 선택할 fallback

가능하면 제공 환경이 사용하는 지형·구역 명칭을 쓰고, “최대한 많이 수집”처럼 선택 기준이 없는 문장을 피한다. 영상의 특정 거리·시간·로봇별 유불리는 예시이므로 보편 규칙으로 고정하지 않는다. 같은 `policy.pt`에서 전략 규칙 하나만 바꿔 반복 비교해야 정책 변화와 전략 변화를 구분할 수 있다.

## 안전·검증 경계

- 센서·경로 데이터가 불완전하면 보수적인 경로와 fallback 행동을 사용한다.
- 백업의 모델명·키·프롬프트·외부 연결은 현재 환경에 그대로 적용하지 않는다.
- 본선 전략의 허용 범위·문자 제한·제공 LLM은 공식 규정과 제공 환경을 우선한다.
