# NCRC `videos.json` 심층 분석 보고서

> 분석 대상: 사용자가 제공한 `videos.json` 원본 1개
> 분석 방식: 원본 JSON의 모든 플레이리스트·통계·실패 상세 기록·보상 다이얼을 구조적으로 파싱하고, 계산 가능한 관계는 재계산해 검증함.
> 주의: **공식 채점 규칙은 이 파일에 포함되어 있지 않다.** 아래에서 `확정`, `강한 추론`, `가설`을 구분한다.

## 1. 핵심 결론

- 파일에는 영상 **84개**가 있으며, 실패 47개 / 성공 34개 / 대회 기록 3개로 나뉜다.
- 성공 기록 34개는 팀·학교·지형·로봇·학습 회차·영상 URL은 남아 있지만 **`detail`이 모두 빈 객체(`{}`)**다. 성공 정책의 reward 설정·진단·학습 지표는 이 JSON에서 제거되어 있다.
- 실패 기록은 47개이고, 그중 **45개에는 `detail.stats`와 진단/보상 설정이 실제로 들어 있다.** 2개는 상세 지표가 비어 있다.
- 실패 상세에는 `최고 보상`, `지형 난이도`, `낙상률`, `탐색 std`가 반복적으로 기록되어 있고, reward dial의 기본값과 변경값도 들어 있다.
- 공식 `score`, `evaluation`, `rank`, `judge`, `metric`, `채점`, `점수`, `평가`, `순위` 같은 필드는 원본 전체에서 발견되지 않았다. 따라서 이 파일만으로 **예선 공식 채점식은 복원할 수 없다.**
- 반면 **학습 상태 진단 규칙**은 데이터에서 상당히 선명하게 역추론할 수 있다. 특히 `낙상률 20%`, `낙상률 50%`, `지형 난이도 0.5`, `탐색 std 1.0` 부근이 실제 진단 분기점으로 보인다.
- 집계 통계의 `steps`는 `iterations × envs × steps_per_iter`와 **정확히 일치**한다. 현재 값에서는 `21,269,640 × 4,096 × 24 = 2,090,890,690,560`이다.

## 2. 최상위 JSON 구조

```text
videos.json
├─ title / subtitle / edition
├─ zones
│  ├─ flip → 실패 기록
│  ├─ ring → 성공 기록
│  └─ wall → 대회 기록
├─ likeApi
├─ stats
└─ playlists
   ├─ flip (실패 기록)
   ├─ wall (대회 기록)
   └─ ring (성공 기록)
```

`likeApi`에는 별도의 Google Apps Script 엔드포인트가 지정되어 있다. 이 보고서의 핵심은 학습 데이터이므로 엔드포인트 URL 자체는 재기재하지 않는다.

### 3.1 계산 관계 검증

**확정:**

```text
iterations × envs × steps_per_iter
= 21,269,640 × 4,096 × 24
= 2,090,890,690,560
= values.steps
```

즉 `steps`는 별도 센서값이 아니라 적어도 현재 집계에서는 위 식으로 정확히 만들어지는 값이다.

`steps / hours / 3600 ≈ 50.000002 Hz`로 계산된다. 즉 `hours`는 사실상 **50 Hz simulation step을 시간으로 환산한 값**과 일치한다. 정수 시간으로 저장되어 약간의 절삭 오차만 있다.

`falls_n`의 합은 **6,898**이고 `policies=7,195`의 **95.9%**에 해당한다.

## 4. 숨겨진 `falls_curve`의 의미

원본:

```text
bin_w      = 1000
falls_curve = [57.0, 38.0, 25.0, 25.7, 22.0, 23.9, 19.8, 20.0, 19.7, 20.3]
falls_n     = [2480, 1734, 493, 945, 217, 492, 139, 104, 84, 210]
```

### 강한 추론

`bin_w=1000`, 길이 10의 `falls_curve`, 길이 10의 `falls_n`, 그리고 `falls_n` 합이 전체 정책 수와 매우 가까운 점을 함께 보면 다음 구조가 가장 자연스럽다.

```text
학습 iteration 구간(폭 1000)
0~999 / 1000~1999 / ... / 9000 이상(또는 9000~9999)
        ↓
각 구간의 정책 개수     → falls_n
각 구간의 평균 낙상률   → falls_curve
```

| bin | 추정 iteration 구간 | falls_n | falls_curve |
| --- | --- | --- | --- |
| 0 | 0–999 | 2480 | 57.0 |
| 1 | 1,000–1,999 | 1734 | 38.0 |
| 2 | 2,000–2,999 | 493 | 25.0 |
| 3 | 3,000–3,999 | 945 | 25.7 |
| 4 | 4,000–4,999 | 217 | 22.0 |
| 5 | 5,000–5,999 | 492 | 23.9 |
| 6 | 6,000–6,999 | 139 | 19.8 |
| 7 | 7,000–7,999 | 104 | 20.0 |
| 8 | 8,000–8,999 | 84 | 19.7 |
| 9 | 9,000+ | 210 | 20.3 |

`falls_curve`의 단순 평균은 27.14, `falls_n` 가중평균은 39.31다. 저장된 `avg_fall=38.2`와 정확히 같지는 않으므로 `avg_fall`은 다른 포함 기준/가중 방식으로 계산됐을 가능성이 높다.

곡선 자체는 초반 57.0 → 후반 약 20 수준으로 크게 낮아진다. **학습 길이가 늘수록 낙상률이 감소하는 집계 패턴**은 강하게 보이지만, 이 자료만으로 인과관계를 증명하지는 못한다.

## 9. 진단 규칙 역추론

아래는 **공식 소스 코드가 아니라 45개 출력 결과에서 역추론한 규칙**이다. 단, 데이터 분기와 일치도가 매우 높다.

| 판정 | 추정 조건 | 근거 | 신뢰도 |
| --- | --- | --- | --- |
| 낙상률 경고 | `fall_rate >= 20%` | `자주 넘어짐` 25건의 최저값 20.3%; 20% 미만에서는 해당 문구 0건 | 강함 |
| 낙상률 심각 | `fall_rate >= 50%` | `절반 이상 넘어짐` 6건. 실제 관측 최저는 71.0%. 50% 이상인 정상 학습 기록은 모두 이 분기(10회 특수실행 제외) | 강함 |
| 커리큘럼 붕괴 | `terrain_difficulty <= 0.5` | 0.00~0.43에서 `0 수준` 진단. 0.5 초과에서는 0건 | 매우 강함 |
| 탐색 미수렴 | `exploration_std >= 1.0` | 1.0 이상 34건 모두 `탐색 std` 관련 경고. 최저 경고값 1.001 | 매우 강함 |
| 초단기 학습 예외 | 총 10회 | 체크포인트는 100회마다 저장된다는 진단문과 함께 지표 판단을 무효화 | 원문 명시 |

### 9.1 낙상률

- 20% 미만 기록에서는 `자주 넘어짐` 경고가 한 번도 나타나지 않는다.
- 경고가 붙은 최저 낙상률은 **20.3%**다.
- `절반 이상 넘어짐`으로 올라간 기록은 6개이며 실제 값은 71.0%~100.0%다.
- 총 10회짜리 특수 실행은 낙상률 100%여도 '지표 판단 근거가 못 된다'는 별도 예외 처리가 붙는다.

### 9.2 지형 난이도

- `지형 난이도 <= 0.5`인 5개 기록은 **5/5 모두** `지형 난이도가 0 수준` 진단을 받는다.
- 0.5를 넘는 기록에서는 이 특정 진단이 없다.
- 별도로 `시작 3.5 → 1.3`처럼 시작점보다 크게 하락한 경우에는 0.5보다 높아도 '커리큘럼이 쉬운 쪽으로 내려감' 경고가 발생한다.
- 로그에 명시된 시작 난이도는 휴머노이드에서 3.4, 사족에서 3.5가 반복적으로 나타난다.

### 9.3 탐색 std

- 정상 학습 기록에서 `std >= 1.0`인 34개는 **34/34 모두** 탐색 std 관련 경고가 붙는다.
- 1.0 미만에서는 해당 경고가 나타나지 않는다(총 10회 특수실행의 설명 문구 제외).
- 따라서 데이터 생성 로직에 **1.0 경계값이 직접 들어 있을 가능성이 매우 높다.**

## 11. 모델/학습 파이프라인에서 추가로 드러나는 것

- **관절 수:** 휴머노이드 19, 사족 12.
- **정책 파라미터 규모:** 실패 상세의 `meta`에서 휴머노이드 약 0.30M, 사족 약 0.29M이 반복된다.
- **병렬 환경:** `envs=4096`.
- **iteration당 환경별 step:** `steps_per_iter=24`.
- **iteration당 총 step:** `4096 × 24 = 98,304`.
- **정책 동작 주기:** 집계식으로 50 Hz와 일치.
- **체크포인트 간격:** 한 진단문에서 '100회마다 저장'이라고 명시된다.
- **커리큘럼 난이도:** 휴머노이드 시작 3.4, 사족 시작 3.5가 관측되며, 실패 상세에서 최대 약 6.07까지 올라간 사례가 있다.
- **탐색 std 초기값:** 진단 문구가 반복적으로 `초기값(1.0)`이라고 명시한다.

## 12. 관찰 상관 — '최적값'으로 사용하면 안 되는 이유

실패 기록만 대상으로 휴머노이드에서 각 변경 다이얼 값과 지표의 Spearman 상관을 탐색했다. 이 표는 **원인 효과가 아니다.** 참가자가 문제가 생긴 뒤 보상값을 바꿨을 수 있어 역인과가 매우 강하다.

| --- | --- | --- | --- | --- |
| action_rate_l2 | 탐색 std | 25 | +0.847 | 9.18e-08 |

예를 들어 `termination_penalty`는 값이 덜 음수일수록 낙상률이 높게 관측되는 경향이 있으나, 이 자료는 실패 사례만 모은 선택표본이다. **따라서 특정 penalty 값을 추천하는 근거로 쓰면 안 된다.**

## 13. 성공 기록에서 얻을 수 있는 것과 없는 것

### 얻을 수 있음

- 성공으로 분류된 사례의 로봇 종류
- 지형
- 학습 iteration
- 날짜
- 팀/학교
- 영상

### 얻을 수 없음

- 성공 정책의 reward coefficient
- 성공 정책의 최고 보상
- 성공 정책의 최종 terrain difficulty
- 성공 정책의 낙상률
- 성공 정책의 exploration std
- 성공 정책의 진단/튜닝 의도

따라서 현재 데이터만으로 `성공 reward 범위`를 직접 학습하는 것은 불가능하다.

## 14. 공식 채점기 평가 기준에 대해 이 JSON이 말해주는 것

### 확인되는 것

- 학습 과정에서 속도 추종, 회전 추종, 낙상, 자세, 흔들림, 관절 정렬, action smoothness 등을 reward 항목으로 조절한다.
- 운영 측 진단은 최소 `낙상률`, `terrain difficulty`, `exploration std`, `best reward`를 사용한다.
- 커리큘럼 난이도 상승/하락 자체를 정책 품질 신호로 취급한다.

### 확인되지 않는 것

- 예선 최종 점수 계산식
- 항목별 배점
- 공식 통과 threshold
- 평가 episode 수
- 평가 command 분포
- 평가 terrain 구성
- 최종 순위 산식

원본 전체에 `score`, `evaluation`, `judge`, `rank`, `metric`, `점수`, `평가`, `채점`, `순위` 문자열이 없기 때문에, **학습 진단 로직과 공식 채점기를 동일시해서는 안 된다.**

## 15. 추후 학습에 실제로 유용한 정보

이 데이터의 가장 큰 가치는 '정답 reward'가 아니라 **실패 영역과 학습 건강지표의 경계**를 알려준다는 점이다.

1. **낙상률 20% 부근**은 운영 진단에서 불안정 경계로 사용된 흔적이 강하다.
2. **낙상률 50% 이상**은 심각한 정책 실패로 별도 분류되는 것으로 보인다.
3. **terrain difficulty 0.5 이하**는 커리큘럼 붕괴/평지 실패에 가까운 상태로 취급된다.
4. **exploration std 1.0 이상**은 수렴 실패 또는 엔트로피 과다 신호로 반복적으로 경고된다.
5. 성공 기록은 실패보다 학습 iteration이 많은 편이지만, 표본 선택 편향 때문에 목표 iteration으로 직접 사용해서는 안 된다.
6. reward 다이얼의 기본값은 상당히 높은 신뢰도로 복원할 수 있으므로, 추후 자체 실험에서는 **기본값 대비 한두 축만 바꾸고 위 4개 건강지표를 추적하는 방식**이 데이터 해석에 유리하다.

## 16. 데이터 품질과 한계

- 이 JSON은 **연구 기록 전시용**이며 전체 제출 DB라고 보장되지 않는다.
- 실패/성공 영상 선정 과정이 무작위가 아니라면 모든 비교는 selection bias를 가진다.
- 실패 상세 중 2개는 지표/세부정보가 비어 있다.
- `warns` 배열은 47개 모두 비어 있고 `note`도 모두 빈 문자열이어서 현재 버전에서는 예약 필드에 가깝다.
- `ndial` 값은 기록 시기/로봇에 따라 달라져 설정 UI 또는 분석 파이프라인이 중간에 변했을 가능성이 있다.
- `falls_curve`의 bin 의미는 원본에 설명문이 없으므로 iteration 구간이라는 해석은 **강한 추론**이다.
- 공식 채점 기준은 이 파일에서 확인되지 않는다.
