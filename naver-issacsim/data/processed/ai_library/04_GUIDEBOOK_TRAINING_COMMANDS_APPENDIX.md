# 학습·진단·정책 내보내기 작업표

## 실행 전

- 제공 서버의 현재 README와 환경을 먼저 읽는다. Isaac Sim·Isaac Lab 버전에 따라 명령과 import가 달라질 수 있다.
- 학습은 장시간 실행될 수 있으므로 세션이 끊겨도 유지되는 터미널 방식으로 실행한다.
- 서버 시간은 팀의 제한 자원이므로 문서 탐색·대규모 분석보다 학습·필수 검증에 쓴다.

## 반복 루프

현재 H1/Go2 실행은 최신 공식 `/workspace/training` source를 그대로 호출하는 `issacsimz` 절차를 `19_ISSACSIMZ_EXTERNAL_EVIDENCE_CLI.md`에서 먼저 확인한다. 과거 강의·백업의 명령 예시는 현재 flag나 파일 위치를 추측하는 근거로 쓰지 않는다.

1. reward 파일을 한 가설만 반영해 수정한다.
2. 짧은 학습으로 보상·손실·난이도 변화와 실제 행동을 확인한다.
3. 후보 체크포인트로 `play`를 실행해 영상과 진단 리포트를 확인한다.
4. 재현 가능한 후보만 더 긴 학습으로 비교한다.
5. 제출 후보는 정책 파일·환경 설정·기술 개선 설명이 서로 일치하도록 준비한다.

## 산출물 해석

| 산출물 | 사용 |
| --- | --- |
| 학습 로그·TensorBoard | 수렴·불안정·난이도 진행을 보는 보조 증거. |
| `model_best.pt` | 일반 학습의 후보 체크포인트. 충분히 긴 resume에서는 자동 선택값이 아니라 final numbered checkpoint를 기본 후보로 쓴다. |
| `policy.pt` | 제출 전 실제 생성 여부를 확인해야 하는 정책 파일. |
| `env.yaml` | reward·환경 설정의 기록. 리포트와 대조한다. |
| play 영상·진단 리포트 | 점수로 놓치는 실제 실패를 찾는 근거. |

## 자연어 전략 관련

본선에서 자연어는 고수준 목표·우선순위 판단에 쓰이고, 저수준 보행·반사 제어를 대체하지 않는다. 실제 허용 모델·문자 제한·출력 형식은 규정과 제공 환경을 확인한다.
