# NAVER CONNECT Robotics Cup 2026 통합 규정집

이 파일은 AI 상담·개발 판단을 위한 단일 규정 기준이다. 일반 규정, 예선 규정, 본선 규정, 설명회 Q&A를 통합했다. **제출·자격·제재·마감 판단은 최신 공식 공지와 단계별 규정이 최우선**이며, Q&A는 운영 해석으로만 사용한다.

2026-09-21에 Downloads로 받은 예선 규정 HTML과 지원 파일은 `data/processed/reference/regulations/2026_source_snapshots/2026-09-21_preliminary_regulations/`에 원문 보존했다. 이 snapshot은 기존 통합 요약을 자동으로 덮어쓰지 않는다. 일정·제출·서버 제한처럼 시점에 따라 바뀔 수 있는 판단은 해당 HTML과 최신 공식 공지를 다시 대조한다.

## 먼저 지켜야 할 핵심 제한

1. 제출 정책을 만드는 강화학습은 운영진 제공 서버에서만 수행한다. 개인·학교 PC나 외부 GPU에서 학습한 정책으로 제출하면 안 된다.
2. 예선 서버 시간은 팀 합산 총 100시간이다. 서버를 켜고 수행하는 작업은 모두 시간에 포함되며 라운드마다 초기화되지 않는다.
3. 예선에서는 보상 파일만 수정한다. H1은 `training/humanoid/humanoid_rewards.py`, Go2는 `training/quadruped/quadruped_rewards.py`가 대상이다.
4. 팀 내부 private 저장소와 AI 보조 도구는 사용할 수 있지만, 다른 팀과 정책·설정·결과물을 공유하거나 대회 가이드·실습 코드를 공개하면 안 된다.
5. 제공 GPU 서버에 MCP·에이전트·외부 연결을 설치하거나 환경을 변경하지 않는다. 개인 PC에서의 분석·코딩 도구 사용과, 제공 서버에서의 정책 학습을 분리한다.
6. 운영진은 2026-09-21에 개인 PC의 Optuna Ask-and-Tell 후보 계산을 허용한다고 답변했다. 단, 제공 서버 설치·연동은 하지 않고, reward 입력·학습 실행은 참가자가 직접 하며, 제출 정책은 제공 서버에서 생성해야 한다. 이는 서버 자동화 허가가 아니다.

## 규정 적용과 신뢰 순서

- 통합 규정은 대회 전반의 기준이고, 예선·본선 규정은 해당 단계에서 통합 규정과 충돌하면 우선한다.
- 마감일·라운드 일정·본선 추가 시간처럼 변동 가능한 항목은 홈페이지의 최신 공식 공지를 확인한다.
- 설명회 Q&A는 2026-08-14 기준 안내이며, 통합 규정은 2026-08-17 시행이다. 둘이 다르면 규정·후속 공지를 따른다.
- 운영진은 필요한 경우 사전 공지로 규정을 개정할 수 있고, 규정 해석의 최종 권한을 가진다.

## 공통 환경·윤리·권리

- 제공 서버에는 Isaac Sim·Isaac Lab·학습 코드가 사전 설치돼 있다. 정책 제출물은 이 환경에서 생성돼야 한다.
- 생성된 결과물을 개인 PC로 내려받아 실행·관찰·영상 확인하는 것은 허용되지만, 개인 장비에서 새 정책을 학습해 제출하는 것은 금지다.
- 타인의 정책·코드·전략 도용, 타 팀과 결과물 공유·공동 제출, 점수·평가·순위 조작, 계정·자격증명 유출, 외부 환경 학습 정책 제출은 금지다. 위반 시 경고·실격·수상 취소와 향후 3년 재단 행사 참여 제한이 가능하다.
- LLM·Copilot 등 AI 도구 사용 자체는 제한하지 않는다. 다만 제출 정책·설정·전략·코멘트의 최종 책임은 팀에 있고, 운영진의 소명 요구에 설명할 수 있어야 한다.
- 제출물 저작권은 팀에 귀속되지만, 팀은 운영·심사·기록·홍보·교육 목적의 복제·전시·시연·공개 권한을 운영진에 허락한다.

## 예선: 정책 학습과 제출

### 학습·로봇·제출물

- 팀당 제공 환경은 하나이며, 한 시점에는 한 명만 접속해 사용한다.
- 예선의 총 100시간은 팀 전체가 공유한다. 서버 켜짐 시간의 모든 작업이 포함되므로 코드 확인·문서 작성·분석은 개인 PC에서 수행하는 편이 안전하다.
- 로봇은 H1(휴머노이드)과 Go2(사족) 두 종류다. 한 라운드에는 한 로봇만 제출하지만, 전체 순위는 로봇별 최고점을 합산한다. 두 로봇을 모두 제출해야 최대 200점이다.
- 제출물은 `policy.pt`(TorchScript 정책), 자동 생성되는 `env.yaml`, 보상 변경의 의도와 결과를 설명하는 기술 개선 리포트다. `report.html`과 `model_best.pt`는 점검용으로 안내되며 제출물 자체가 아니다.
- 이전 정책은 재제출하거나 이어 학습할 수 있다. 이어 학습은 시간 절약에는 유리하지만 커리큘럼 난이도가 낮은 단계로 돌아갈 수 있으므로 최종 정책은 충분히 검증한다.

### 평가와 제출

| 로봇별 배점 | 내용 |
| --- | --- |
| 70점 | 여러 지형·명령 시나리오에서의 시뮬레이션 성능 |
| 20점 | 보상 변경 의도와 실제 `env.yaml` 설정의 일치 |
| 10점 | 기술 개선 리포트의 설명 품질 |

- H1은 평지 균형·전진·좌우·회전·요철·경사·밀침 회복, Go2는 전진·전방위·험지·경사·계단·밀침 회복 등 격리 시나리오에서 평가된다.
- 라운드별 마감 전에는 제출을 수정할 수 있으나, 마감 후 제출·수정은 인정되지 않는다. 일부 라운드에 참여하지 않아도 별도 불이익은 없고 로봇별 최고점이 반영된다.
- 동점은 시뮬레이션 점수, 설계 의도 분석, 먼저 제출한 순서로 판정한다.
- 제출은 서버 안에서 자동으로 끝나는 방식이 아니라 결과물을 내려받아 공식 홈페이지에서 올리고 코멘트를 입력하는 방식이다.

### 2026-10-02 운영진 Q&A — 기술 개선 리포트의 설정 비교 기준

사용자가 제공한 [운영진 답변 원문](../incoming/other/reviewed/2026-10-02_SUBMISSION_REPORT_BASELINE_REFERENCE_ORGANIZER_REPLY.md)에 따르면, 기술 개선 리포트에서 reward/config 변경의 전→후를 적을 때 **배포 시작값 기준**과 **같은 로봇의 직전 라운드 제출 설정 기준**을 모두 사용할 수 있다. 이는 Q&A 보조 해석이며 최신 공식 공지·규정과 충돌하면 후자를 우선한다.

- 배포 시작값 기준은 처음 받은 파일의 값과 최종 설정을 비교한다.
- 직전 라운드 제출 설정 기준을 쓸 때는 첫 줄에 비교 기준을 명시한다. 예: `기준: 4라운드 제출 설정(휴머노이드)`.
- 기준을 명시하지 않으면 배포 시작값과 비교하는 것으로 평가된다.
- 이번에 변경한 항목은 선택한 기준 대비 전→후를 적는다.
- 직전 라운드 기준에서 손대지 않은 항목은 개별로 적거나, 실제로 같은 로봇의 직전 제출과 동일할 때만 `나머지는 직전 제출 그대로`라고 쓸 수 있다.
- 어느 방식을 사용하더라도 리포트에 적힌 **최종값은 제출한 `env.yaml`과 일치해야 한다.**

이 답변은 제출 리포트의 비교·서술 방식을 명확히 한 것이며, reward 수정 허용 범위, 공식 서버 학습 의무, 제출 provenance 규칙을 완화하거나 변경하는 것으로 해석하지 않는다.

## 본선·결승: 정책과 LLM 전략

- 예선 상위 32팀은 온라인 본선에서 1:1 토너먼트를 치르고, 상위 4팀이 오프라인 결승으로 진출한다. 각 대결은 5전 3선승이다.
- 예선 최종 H1·Go2 정책이 기본 출전 정책이며, 본선·결승 각 마감 전에는 제공 서버에서 추가 학습한 정책으로 교체할 수 있다.
- 매 라운드 H1 또는 Go2 중 출전 로봇을 선택한다. 같은 시리즈에서 마감된 정책 자체를 임의로 바꾸면 안 된다.
- 전략 텍스트는 자연어 300자 이하다. 운영진 제공 Gemini가 목표 큐브 우선순위를 해석하며, 참가자는 별도 LLM을 반입·연동하지 않는다.
- 경기 시간은 180초다. 큐브 1개는 +100, 낙상 1회는 -50, 차량 충돌 1회는 -30점이다.
- 동점은 큐브 수집 수 → 낙상 횟수 → 차량 충돌 횟수 → 첫 큐브 수집 시각 → 마지막 큐브 수집 시각 순으로 판정하고, 모두 같으면 재경기한다.
- 프롬프트 인젝션 등 시스템 조작 지시, 실시간 반사 회피처럼 LLM 지연을 무시한 지시, 부적절한 언어는 금지다. 전략은 구역·큐브 우선순위 수준의 계획이어야 한다.

## 개발·자료 취급 실무

- 공개 논문·기술 문서·저장소를 읽고 직접 실험하는 것은 허용된다. 값의 출처보다 어떤 가설로 바꿨고 결과가 어땠는지 설명할 수 있어야 한다.
- 공개 researchlog처럼 읽기 전용으로 공개된 관찰 자료는 개인 PC에서 참고할 수 있다. 다만 인증·비공개 endpoint를 조회하지 않고, 타 팀의 공개 사례도 우리 공식 Run·제출 provenance·인과 효과로 바꾸어 서술하지 않는다.
- 개인 PC의 LLM·Copilot·분석 에이전트는 사용 가능하지만, 대회 제공 자료를 공개 서비스에 올려 제3자가 접근하게 하면 안 된다.
- 공식 준수사항 영상은 LLM에게 다음 reward 후보를 묻는 것과 참가자가 직접 작성한 반복 실행 스크립트를 허용 사례로 제시한다. 다만 선택 이유와 실제 결과를 팀이 설명할 수 있어야 하며, 제공 서버에 새 에이전트·도구·외부 연결을 설치하는 것은 허용되지 않는다.
- 같은 영상은 제출 파일·reward/config와 공식 서버의 run log·checkpoint를 대조할 수 있음을 안내한다. 정책·설정·실험 기록의 추적 가능성을 유지한다.
- 팀 내부 private GitHub 저장소는 허용 안내가 있으나, 다른 팀과의 공유나 대회 가이드·실습 코드의 공개 저장소 업로드는 금지다.
- Q&A에 따르면 서버는 일정 시간 유휴 시 종료될 수 있고 참가자 설치물이 유지되지 않을 수 있다. 서버에는 최소한의 학습 작업만 두고, 문서·분석·버전 관리는 개인 작업공간에서 수행한다.

## AI 응답 규칙

- 규정 질문에는 이 문서의 절과 근거 규정(통합·예선·본선)을 함께 제시한다.
- 개인 NVIDIA 서버는 코드 이해·정책 관찰·분석에는 사용할 수 있어도, 그곳에서 학습한 정책을 대회 제출물로 사용해도 된다고 안내하지 않는다.
- 일정·마감·서버 세부 사양은 변동 가능하므로 최신 홈페이지 공지를 확인하도록 안내한다.
- Q&A만으로 규정 예외를 만들지 않는다.
