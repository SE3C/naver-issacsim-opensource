# 연습 게임 엔진 구조와 검증 경계

## 아키텍처 한 줄

연습 엔진은 Isaac Sim 안에서 맵·큐브·차량·로봇·정책·경로계획·점수·백엔드 통신을 묶어 경기를 재현한다. `engine.py`가 수명주기와 물리를 주도하고, `cube_game.py`가 목표물과 점수 상태를, `backend_client.py`가 외부 서비스와의 연결을 담당한다.

## 읽는 순서

1. `practice_sim/README.md.md`: 실행 인자와 연습 목적.
2. `engine.py.md`: world 초기화, 맵·로봇·경기 루프, 낙상·충돌 처리.
3. `cube_game.py.md`: 큐브 생성·수집·점수 상태.
4. `practice_sim.py.md`: 연습 실행의 진입점.
5. `backend_client.py.md`: 결과 전달·서비스 연동 참고.

## 구현에서 확인할 수 있는 핵심

- 맵과 spawn, 로봇 종류, 정책 경로는 경기 시작 전 설정되고 매치 단위로 초기화된다.
- 관측은 로봇 상태·지형·목표를 바탕으로 만들며, 저수준 정책은 속도·행동 명령을 받는다.
- 큐브 수집, 낙상, 충돌, 시간 경과가 점수와 경기 상태에 영향을 준다.
- 카메라·스트리밍·로그는 디버깅과 관찰을 돕지만 경기 규정 자체는 아니다.

## 검증 원칙

- 코드의 상수·점수·타이브레이커를 공식 규정처럼 인용하지 않는다. 연습 백업은 특정 시점의 구현이다.
- API key, `practice_key` 계열 파일, backend URL·토큰은 열람·복사·재사용 대상이 아니다.
- 개인 환경에서 정책·경로 전략을 테스트할 수는 있어도, 공식 서버 정책 학습과 공식 점수 판정을 대체하지 않는다.

## 개발 질문에 답하는 방식

함수 동작을 묻는 질문은 원문 코드의 함수명과 호출 경로를 확인해 답한다. 경기 규칙을 묻는 질문은 `12_2026_UNIFIED_REGULATIONS.md`를 먼저 본다.
