# 공개 범위와 준비안

2026-10-23 초안. 사용자 결정: 기존 5개 저장소는 보존하고 `SE3C/naver-issacsim-opensource` 단일 새 저장소를 준비한다. 라이선스는 미정이다. 파일별 공개 범위는 계속 검토한다.

## 1. 저장소별 분리 구상

| 저장소 | 공개 후보 | 비공개 유지 또는 권한 확인 대상 |
| --- | --- | --- |
| naver-issacsim | 자체 실험 해석·방법론·정리 도구 | 운영진 DM, 제공 원문, 강의 변환물, 정책·설정·결과물 공개 범위 |
| naver-issacsim-originals | 공개 허가가 확인된 자료의 출처 안내 | 강의·실습·공식 training 스냅샷, 원본 evidence와 대용량 보관물 |
| naver-issacsim-nvidia | 분리 가능한 자체 setup·보조 스크립트 | 공식 training 코드 및 그 파생물의 재배포 권한 |
| naver-issacsim-eval | 자체 평가기·실행기·사용법 | 정책·평가 ZIP, 제공 자료 유래 부분, 개인 경로가 포함된 메타데이터 |
| issacsimz | 자체 orchestration/evidence 코드 | 의존성·기여분의 권리와 라이선스 범위 |

파일명이나 현재 저장소 위치만으로 공개 가능성을 판정하지 않는다. `private-` Release 태그도 공개 전환 시 비공개를 유지해 주는 장치가 아니다.

## 2. 공개 형태 선택

**자체 코드 중심의 새 공개용 사본**을 만드는 방식을 사용자와 확정했다. 기존 보관 저장소는 현재 설정을 유지하고, 제공 자료·연구 이력을 보존한다. 자체 코드·방법론은 가능한 많이 살리며, 제공 자료가 섞인 결과물은 공개용 파생물을 분리할 수 있는지 검토한다.

기존 저장소 자체를 공개하는 방식을 택하면 현재 파일뿐 아니라 모든 공개 ref·과거 커밋·Release 첨부의 정리가 필요하다. 브랜치 삭제만으로 과거 자료와 Release가 모두 제거된다고 가정하지 않는다.

## 3. 작업 단계

1. 자료별 권한 확인: 공식 코드·강의·실습·DM과 팀 정책/결과물의 공개 가능 범위를 확인한다. 대회 종료만으로 제한이 해제됐다고 가정하지 않는다.
2. 공개 목록 확정: 파일/디렉터리 및 Release별로 `공개`, `제외`, `권한 확인 필요`를 지정한다. 원본은 별도 비공개 보관한다.
3. 공개용 사본 준비: 허용된 파일만 복사한다. 공개용으로 비식별 처리한 산출물은 원본과 구별하고 provenance·변경 내역을 남긴다.
4. 라이선스 정리: 자체 작성 코드의 권리와 기여분을 확인하고 라이선스·필요한 제3자 고지를 작성한다. 코드/모델/데이터의 적용 범위를 명시한다.
5. 최종 검사: 공개용 트리·Git 이력·배포 ZIP/tar·Release 설명과 첨부를 대상으로 자격증명·개인정보·제외 자료가 없는지 확인한다.
6. 사용자 검토 후 공개: 확인되지 않은 항목을 해결하거나 명시적으로 제외한 뒤 공개한다. 저장소 공개 설정은 이 문서 작성만으로 바꾸지 않는다.

## 4. 먼저 결정할 사항

- 자체 코드만 공개할지, 실험 분석과 정책/평가 결과도 포함할지.
- 제공 자료는 계속 비공개로 둘지, 운영진에게 공개 허가를 요청할지.
- 운영진 대화는 원문 제외·익명 요약·동의 후 공개 중 무엇으로 할지.
- 커밋 작성자 메일을 유지할지, 새 공개 이력에서 비식별 처리할지.
- 새 공개 저장소 분리는 확정. 최종 라이선스와 파일별 공개 범위는 미확정.

현재는 결정 목록을 마련한 단계다. 이 초안에 따라 자료 삭제·이력 재작성·공개 전환을 자동 실행하지 않는다.
