# Optuna 기존 분석 세션 — 최소 개선 전달 자료

`OPTUNA_EXISTING_SESSION_IMPROVEMENT_20261015.zip`과 `Optuna_기존세션_개선요청_20261015.txt`를 **기존 Optuna 검토 세션에** 전달한다. H1 추가 가설 탐색은 별도 새 세션이다. 이 묶음은 개선 요청용 입력이며 개선 완료본이 아니다.

## 구성과 우선순위

- `originals/`: 처음 받은 도구 ZIP, 별도 calibrator HTML, 당시 검토 프롬프트. 변경하지 않은 원본이며 도구 ZIP을 풀어 최소 개선한다. 과거 프롬프트와 현재 요청이 충돌하면 현재 `PROMPT_ko.txt`가 우선한다.
- `audit/`: 외주 검토 보고서와 CPU 테스트·합성 fixture 등 19개 산출물 원문. 외부 작성자가 보고한 결과이며 이번 포장 과정에서 테스트를 다시 실행하지 않았다. 합성 trial은 실제 학습 결과가 아니다.
- `context/REVIEW_INTAKE.md`: 원본 코드와 대조한 결함·채택 범위·미검증 사항.
- `context/15_OPTUNA_REWARD_DECISION_ENGINE.md`: 현재 프로젝트의 Optuna 사용 경계. 날짜별 역사 서술은 최신 수납 문서와 구분한다.
- `context/ORGANIZER_PERSONAL_ASK_TELL_APPROVAL.md`: 운영진 답변 보존본. 개인 PC 후보 계산, 참가자의 직접 reward 수정·학습, 공식 서버 학습 정책 사용이라는 경계를 유지한다.
- `INPUT_FILES.json`: 실제 포함 파일의 원본 경로·크기와 저장소 revision. 원문 상대링크 일부는 전달 자료 밖을 가리키므로 제공되지 않은 자료까지 확인했다고 쓰지 않는다.

## 이번에 할 가치가 있는 것

요청마다 같은 seeded sampler를 재생성하는 문제, Ask/Tell 결합, 점수·objective 불일치, 중복·실패·재시작 상태를 먼저 고친다. UI의 보정값을 검증된 공식 점수처럼 쓰지 않는다. 별도 HTML도 검토하되 필요한 버튼·표시·안내만 정정하고 UI 통합이나 새 evaluator로 범위를 넓히지 않는다.

실제 사용을 위한 objective와 비교 조건은 별도 승인이 필요하다. 그 조건이 없으면 Tell을 막고 후보 Ask·진단/수동 기록 경로만 제공한다. 기존 study를 조용히 바꾸거나 과거 분석을 fabricated trial로 입력하지 않는다. 실제 Windows 결과 ZIP·episode 원자료·checkpoint는 이 패킷에 없으므로 자동 adapter나 실제 정책 성능 검증을 구현·완료했다고 주장하지 않는다.

## 결과와 실행 제한

원본을 보존하고 별도 개선본으로 작업한다. CPU 임시 DB·합성 fixture 테스트만 사용한다. 실제 실행 명령·exit code·버전·미검증 항목을 남기고, 개선 프로그램 전체·사용법·보고서·테스트 파일 전체를 **단일 ZIP**으로 반환한다. GPU·학습·영상·export·공식 서버 작업은 금지 범위다. 이 준비 작업은 새 Optuna trial이나 학습 실행을 승인하지 않는다.
