이 요청은 기존 Optuna 코드 검토·CPU 분석 세션에서 이어서 보낸다. 첨부 OPTUNA_EXISTING_SESSION_IMPROVEMENT_20261015.zip에는 원본 도구, 별도 HTML, 네가 작성한 REVIEW_REPORT_ko.md와 CPU 근거, 현재 채택 경계가 있다. START_HERE.md를 먼저 읽고 앞서 확인한 결함을 최소 범위로 개선해줘. H1 새 가설 탐색은 별도 새 세션에서 진행하므로 여기서 다시 하지 마. 전체 재분석이나 새 평가기 개발도 하지 마.

목표는 개인 PC용 Optuna Ask-and-Tell의 신뢰성이다. 기존 app.py/UI를 필요한 만큼만 고치고, 기존 평가기나 실제 reward/학습 코드는 변경하지 마.

이번 구현 범위:
1. 요청마다 같은 seeded sampler를 다시 만드는 버그를 고쳐. sampler 수명과 재시작 정책을 명시하고, 초기 후보 반복·재시작 회귀 테스트를 추가해. 대형 분산/동시사용 시스템은 필요 없어.
2. Ask/Tell/다음 Ask를 분리하고 명시적으로 실행하게 해. trial 상태와 고정 reward/search-space·비교 조건을 연결하고 stage 이름 충돌, 중복 Tell, 실패/abandon, 재시작 후 DB 상태 조회를 최소 구현해. SQLite를 기준으로 두고 보조 history 장애가 완료 여부를 숨기지 않게 해.
3. score와 objective가 모순되게 저장되지 않도록 하나의 canonical 값으로 처리해. 미입력·NaN·범위 밖 값은 거부하고, 이전 UI 값이나 가짜 0으로 채우지 마. HOLD/REJECT도 임의 숫자로 바꾸지 마.
4. 자체 evaluator 실행·자동 평가→Tell 연결은 기본 경로에서 차단해. UI 서버는 127.0.0.1만 기본 사용하고, 누락된 가짜 CLI 안내는 제거하거나 실제 동작하게 해.
5. TERM50 고정 보정·LOG heuristic은 자동 objective에서 빼고 참고 진단과 구분해. 새 공식점수 예측식이나 임의 목적함수를 만들지 마. 목적함수/비교 조건이 미정이면 Ask와 진단 기록만 가능하게 하고 Tell은 막아.
6. 탐색 항목·범위는 명시 설정으로 분리해. 실제 사용한 action=-0.0001 같은 값도 표현 가능해야 하지만 기존 study의 범위를 조용히 변경하거나 새 탐색 범위를 임의 확정하지 마.

아직 없는 미래 Run ID를 Ask의 필수 입력으로 만들지 마. 결과를 연결할 때 실제 확인된 Run/checkpoint SHA·평가 식별자·protocol/부모/학습량을 기록하고, 모르는 값은 미확인으로 남겨. 경로 이름만으로 정책 동일성을 확정하지 마.

이번에는 실제 Windows 평가 ZIP adapter 전체 구현, evaluator worker 개선, GPU/영상/학습/export, 공식 서버 접속·설치·연동·종료는 제외해. 기존 평가기 스키마나 실제 관측이 입력에 없으면 추측해 만들지 마. 단일 사용자 PC 도구에 불필요한 기능·리팩터링을 늘리지 마. 운영진 답변과 AI 문서는 사용 경계의 근거이지 실제 운영 study/trial 생성·학습 실행의 추가 승인이 아니다. 목적함수·비교 조건이 미정이라면 Tell 차단을 구현한 상태와 실제 최적화 준비가 미완료인 상태를 구분해 보고해.

CPU-only 임시 DB/합성 fixture로 주요 버그와 실패 경로를 테스트해. 실제 실행한 명령·exit code·Optuna 버전과 미검증 범위를 구분하고, 코드 검토만 한 테스트를 PASS로 쓰지 마. 원본은 보존하고 별도 개선본을 만들어.

최종 결과는 개선된 실행 파일 전체, 짧은 사용법, 변경 요약, 테스트 코드/결과와 보고서를 모두 합친 단일 ZIP으로 줘. 단순 패치만 주지 말고 원본과 구분되는 버전으로, 새 GPU 작업 없이 바로 CPU 검토할 수 있게 해줘. 지금 바로 가능한 활용(후보 Ask·수동 결과 기록)과 아직 막아야 할 활용(Tell 조건 미충족·공식 점수 예측·서버 연동), 후속 개선에 꼭 필요한 실제 입력을 짧게 구분해. 단순히 더 많은 기능을 제안하는 것으로 구현을 대신하지 마.
